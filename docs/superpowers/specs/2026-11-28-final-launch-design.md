# LES SURGUT: подготовка к финальному запуску

## Цель

Обновить визуальные материалы четырёх домов профессиональными новогодними фотосессиями, сделать новые кадры заметными на ключевых страницах и добавить безопасную систему «Горячих дат», которую заказчица сможет обслуживать без секретов в публичном коде.

## Ограничения

- Сохраняются существующие URL, тексты, обычные тарифы, видео, контакты, формы и визуальная система.
- Публикация не выполняется до отдельного подтверждения.
- `content.json` остаётся единым источником изменяемого контента.
- GitHub Pages остаётся статическим хостингом с базовым путём `/les-surgut-site/`.
- Исходные фотографии не изменяются и не удаляются.

## Рассмотренные подходы

1. **Внешняя CMS с OAuth.** Лучший интерфейс в браузере, но требует отдельного сервиса/аккаунта и настройки авторизации. Без согласования не используется.
2. **Только ручное редактирование JSON.** Совместимо со статическим сайтом, но не отвечает требованию удобства для заказчицы.
3. **Существующий визуальный редактор + авторизованный GitHub Actions workflow.** Редактор даёт русскую мобильную форму и предпросмотр, а ручной workflow GitHub выполняет безопасное добавление, изменение, бронирование, отключение и удаление предложений с пересборкой сайта. Секреты не попадают в браузер. Выбран этот подход как минимальный полноценный вариант без нового платного сервиса.

## Фотографии

- 76 новых оригиналов преобразуются в полные WebP (длинная сторона не более 2400 px, качество 84) и адаптивные WebP (ширина/длинная сторона до 720 px, качество 80) с учётом EXIF и без кадрирования.
- Имена и порядок задаются явными списками, без автоматической сортировки.
- `content.json` хранит обложку и полную последовательность каждой галереи.
- `photo-library.json` связывает подходящие новые кадры с блоком «Удобства дома».
- Главная, каталог и страницы домов используют те же оптимизированные файлы без копий.
- Общая галерея получает выбранные кадры четырёх домов с фактическими категориями и без удаления существующих материалов территории/услуг.

## Горячие даты

В `content.json` добавляется массив `hotDates`. Предложение содержит `id`, `house`, `date`, `guests`, `terms`, `regularPrice`, `salePrice`, `publishFrom`, `expiresAt`, `active`, `booked` и `comment`. Процент скидки рассчитывается на клиенте и в скрипте управления, но не хранится как независимая редактируемая величина.

Общая чистая функция фильтрует предложения по времени `Asia/Yekaterinburg`: только активные, не забронированные, не просроченные и с датой отдыха от текущего дня до семи дней включительно. Недостоверная доступность не обещается: все CTA говорят об уточнении и открывают существующую форму бронирования с заполненными домом, датой и условиями акции.

Верхняя полоса присутствует на основных страницах и ведёт к `/#hot-dates`. На главной всегда есть компактный раздел: карточки при наличии валидных предложений, нейтральный текст — при отсутствии. На странице дома карточки показываются только для этого дома; календарь получает ненавязчивую отметку скидки, но дата по-прежнему требует подтверждения менеджера.

## Управление

Редактор получает отдельный понятный раздел для добавления, изменения статуса и удаления горячих дат, автоматического расчёта скидки и предпросмотра. Локальный черновик не выдаётся за публикацию.

Скрипт `scripts/update-hot-dates.mjs` валидирует те же поля и выполняет операции из авторизованного GitHub Actions workflow. Workflow запускается вручную владельцем репозитория, обновляет исходную ветку, собирает сайт и публикует результат без force-push. Для его работы потребуется включённое разрешение GitHub Actions `Read and write`; внешние токены и сервисы не нужны.

## Проверка

- Автоматические тесты покрывают фильтрацию по времени Сургута, границу семи дней, статусы, истечение, цены и процент скидки.
- Проверяется точный порядок 101 кадра, уникальность, наличие двух вариантов и совпадение пропорций.
- `npm run build`, `npm run check`, дополнительные проверки ссылок и размеров обязательны.
- Локальная сборка проверяется на ширинах 320, 375, 390, 430, 768, 1024, 1440 и 1920 px; формируются требуемые скриншоты.

## Не входит в текущую локальную реализацию

- Автоматическое подтверждение фактической свободности дат без достоверного внешнего календаря.
- Публичная публикация до отдельного подтверждения пользователя.
- Подключение платной CMS или нового внешнего аккаунта.
